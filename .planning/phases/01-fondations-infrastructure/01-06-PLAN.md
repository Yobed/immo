# Plan 01-06: Google OAuth Onboarding (inscription + sélection rôle)

## Goal
Permettre l'inscription via Google avec sélection du rôle (locataire/propriétaire) et complétion du profil, identique au flow email.

## Context
- La page `/login` a déjà un bouton "Continuer avec Google" (`signInWithOAuth`)
- La page `/register` n'a PAS de bouton Google
- Le callback `/auth/callback` redirige toujours vers `/` — pas de distinction nouveau utilisateur
- Le trigger `handle_new_user` lit `raw_user_meta_data.role` — mais Google OAuth ne passe jamais ce champ → role par défaut = `locataire`
- Il faut une page `/auth/complete-profile` pour collecter role + confirmer nom après Google OAuth

## Requirements
- REG-G1: Bouton "Continuer avec Google" sur la page `/register`
- REG-G2: Après Google OAuth (nouveau user), rediriger vers `/auth/complete-profile`
- REG-G3: Page `/auth/complete-profile` : nom pré-rempli depuis Google + sélection rôle
- REG-G4: Soumission met à jour `profiles.role` et `profiles.full_name` via API
- REG-G5: Utilisateur existant (Google) → pas de complete-profile → dashboard direct

## Implementation Notes

### Détection nouveau utilisateur dans callback
Supabase ne renvoie pas de flag "is_new_user" direct. Stratégie :
- Après `exchangeCodeForSession`, appeler `supabase.auth.getUser()`
- Lire `profiles` row pour cet user
- Si `full_name = ''` ET `raw_user_meta_data.provider = 'google'` → nouveau → redirect `/auth/complete-profile`
- Sinon → redirect vers dashboard selon role

### Route callback mise à jour
`/auth/callback` doit :
1. `exchangeCodeForSession` (code)
2. Récupérer user + profile
3. Si `provider == 'google'` ET `profile.full_name == ''` → `/auth/complete-profile`
4. Sinon → `/dashboard` (pro) ou `/` (client)

### Page complete-profile
- Client Component
- Lire user depuis `supabase.auth.getUser()` (client)
- Pré-remplir `full_name` depuis `user.user_metadata.full_name` (Google le fournit)
- Sélecteur Locataire / Propriétaire (même UI que register)
- Submit → `PATCH /api/auth/complete-profile` → update `profiles` → redirect dashboard

### API complete-profile
`apps/web/app/api/auth/complete-profile/route.ts`
- `PATCH` uniquement (user déjà connecté)
- Guard : user must be authenticated
- `supabase.from('profiles').update({ full_name, role }).eq('id', user.id)`
- Retourne `{ ok: true }`

## Tasks

### Task 1 — Bouton Google sur /register
**File:** `apps/web/app/(auth)/register/page.tsx`
- Ajouter state `googleLoading`
- Ajouter fonction `handleGoogleLogin` identique à login (redirectTo: `/auth/callback`)
- Ajouter bouton Google + séparateur "ou" au-dessus du form
- Garder form email/password intact

### Task 2 — Mise à jour callback route
**File:** `apps/web/app/(auth)/callback/route.ts`
- Après `exchangeCodeForSession`, récupérer `user` et `profile`
- Logique :
  ```
  if provider == 'google' && profile.full_name == '':
    redirect /auth/complete-profile
  else if role == 'proprietaire':
    redirect /dashboard
  else:
    redirect /
  ```
- Utiliser service client (cookie-based, même pattern qu'actuellement)

### Task 3 — Page /auth/complete-profile
**File:** `apps/web/app/(auth)/complete-profile/page.tsx`
- `'use client'`
- `useEffect` : récupérer `user` via `supabase.auth.getUser()`, pré-remplir nom
- Form : input nom + sélecteur radio Locataire/Propriétaire (même UI que register)
- Submit : `fetch('/api/auth/complete-profile', { method: 'PATCH', body: JSON.stringify({ full_name, role }) })`
- Success : `window.location.href = role === 'proprietaire' ? '/dashboard' : '/'`
- Si user non connecté : `router.push('/login')`

### Task 4 — API PATCH /api/auth/complete-profile
**File:** `apps/web/app/api/auth/complete-profile/route.ts`
- `export async function PATCH(req: Request)`
- `createClient()` (server)
- Guard `!user` → 401
- Valider body : `{ full_name: string, role: 'locataire' | 'proprietaire' }`
- `supabase.from('profiles').update({ full_name, role }).eq('id', user.id)`
- Return `{ ok: true }` 200

## Success Criteria
1. Sur `/register`, le bouton "Continuer avec Google" est visible et fonctionnel
2. Nouvelle inscription Google → redirigé vers `/auth/complete-profile` avec nom pré-rempli
3. Sélection rôle → profile mis à jour en BDD → redirect dashboard correct
4. Reconnexion Google (user existant) → pas de complete-profile → dashboard direct
5. Page `/auth/complete-profile` protégée (redirect /login si non connecté)

## Wave
Single wave — 4 tasks séquentielles (pas de parallélisation, même fichier pour Tasks 1+2)
